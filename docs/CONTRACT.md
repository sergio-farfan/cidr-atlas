# CIDR Atlas implementation contract

Author: Sergio Farfan <sergio.farfan@gmail.com>

Monorepo: `packages/cidr_core` (pure Dart), `packages/cidr_data` (Dart SQLite/imports), `packages/cidr_oci` (pure Dart OCI CLI adapter), `packages/cidr_cli`, `apps/cidr_atlas` (Flutter macOS first).

Core public API, exported from `package:cidr_core/cidr_core.dart`:

- `Cidr.parse(String input)` rejects invalid prefixes and host bits rather than silently changing the requested network. Properties: `canonical` String, `prefixLength` int, `version` int, `addressCount` BigInt. Methods: `contains(Cidr)`, `overlaps(Cidr)`.
- enums `PrefixKind { allocation, vcn, subnet }`, `PrefixStatus { planned, reserved, active, retired }`.
- Immutable `PrefixRecord`: required named String `id`, `cidr`, `name`, `routingDomain`; named `kind` default `PrefixKind.vcn`, `status` default `PrefixStatus.reserved`; optional String fields default empty: `customer`, `tenancy`, `region`, `compartment`, `environment`, `owner`, `resourceId`, `vcnId`, `parentId`, `notes`, `source`; nullable DateTime `verifiedAt`. `toJson()`, `PrefixRecord.fromJson(Map<String,dynamic>)`, `copyWith(...)`.
- `Conflict`: `PrefixRecord first`, `second`; String `reason`.
- `InventoryRules.conflicts(List<PrefixRecord>)` returns List<Conflict>. Only same routing domain conflicts. Retired prefixes ignored. Valid parent containment requires explicit, valid parentId chain OR VCN/subnet OCI resource relationship (matching vcn.resourceId and subnet.vcnId, same tenancy/region/domain). Arbitrary numeric containment is a conflict. Nonoverlapping unrelated resources are allowed.
- `InventoryRules.validate(List<PrefixRecord>)` returns List<String> for invalid CIDRs, blank identities/domains, duplicate ids, invalid/missing parent links, containment/kind mismatch and cycles. Conflicts remain reviewable, not structural validation errors.
- `InventoryRules.available({required Cidr parent, required int prefixLength, required List<PrefixRecord> records, required String routingDomain, String? parentId, int limit = 8})` returns List<Cidr>; ignores retired entries. With parentId, validates the selected pool and ignores only that record and its explicit valid ancestors. Without it, every overlapping existing range blocks. Reject impossible prefix lengths.
- `AddressPolicy { generic, ociIpv4Subnet }`, `DemandBasis { current, peak }`. `AddressDemand({required BigInt addresses, required int growthPercent, BigInt? additionalAddresses, DemandBasis basis = DemandBasis.current})` exposes exact `targetAddresses = ceil(addresses * (100 + growthPercent) / 100) + additionalAddresses`. Growth is explicit and nonnegative; basis labels the input rather than removing an explicit allowance.
- `CidrDetails.from(Cidr, {AddressPolicy policy = AddressPolicy.generic})` exposes exact totals, host bits, network/range, nullable IPv4 mask, separately nullable provider assignable count/range, policy note, and `containingSupernet(int)`. OCI IPv4 subnet policy accepts only `/16..30`, subtracting three reserved addresses. Generic policy does not invent assignable counts for IPv4 or IPv6.
- `AddressInterval` uses inclusive `BigInt start/end` and an IP version. `AddressSpaceSummary` exposes disjoint free/blocked intervals, exact total/free/blocked addresses, total/free aligned slots, and largest free CIDR. Partial occupancy blocks a complete candidate slot without equating free addresses with free slots.
- `AddressPlanner.plan({required Cidr parent, required String routingDomain, required List<PrefixRecord> records, String? parentId, int? prefixLength, AddressDemand? demand, AddressPolicy policy = AddressPolicy.generic, int limit = 12})` requires exactly one of prefix or demand. Demand sizing initially supports OCI IPv4 subnets. Parent/domain/ancestor rules match `InventoryRules.available`, whose ascending ordering remains unchanged. Planning ranks maximal aligned free blocks by smallest fit, then address, considering aligned edges before bounded interior alternatives. `AllocationPlan` contains summary, prefixLength, nullable targetAddresses, bounded candidates, warnings; each candidate contains CIDR, details, rationale. `toJson()` uses public field names and decimal strings for all BigInt values. Availability is conditional on inventory coverage.

Data API exported from `package:cidr_data/cidr_data.dart`:

- `InventoryStore.open(String path)`, `InventoryStore.memory()`; synchronous `List<PrefixRecord> list()`, `void save(PrefixRecord, {bool rejectConflicts = false})`, `void delete(String id)`, `void saveAll(List<PrefixRecord>)`, `List<AuditEntry> history({int limit = 100})`, `void close()`.
- `AuditEntry`: String `action`, `summary`; DateTime `at`.
- Atomic saves validate combined structure. rejectConflicts checks the candidate within the same write transaction for allocation workflows. Store enforces structure but allows conflict records so discovered overlaps are visible.
- `InventoryStore.reserve(PrefixRecord)` creates a new record only, checking duplicate IDs, combined structure, and current conflicts inside one write transaction. Failure rolls back both record and audit writes. Planner UI/CLI use this path; imports retain their conflict-review behavior.
- `ImportPreview`: List<PrefixRecord> `records`; List<String> `errors`, `warnings`; String `source`; bool `get canApply` (nonempty records and no errors).
- `ImportPreview.emptyRecordsMessage` is the canonical existing empty-record diagnostic. `isEmptyResult` classifies an empty record list with no errors other than that diagnostic. Raw errors and `canApply` remain unchanged; classification is presentation-only and never permits an empty apply.
- `InventoryImport.csv(String, {List<PrefixRecord> existingRecords = const []})`, `InventoryImport.json(String, {required String routingDomain, List<PrefixRecord> existingRecords = const []})`, `InventoryImport.exportCsv(List<PrefixRecord>)`, `InventoryImport.exportJson(List<PrefixRecord>)`.
- `InventoryStore.mergedImportRecords(ImportPreview)` returns the full dry-run inventory using the same merge rules as applyImport; `InventoryStore.applyImport(ImportPreview)` applies atomically, merging by id and preserving existing owner/notes/status/parentId/environment/customer where source is OCI. No absent entries deleted or retired. Audit coverage warning always explicit.
- OCI imports retain `ImportPreview.source == 'OCI JSON'` and incoming record source `oci`; merge protections depend on those identities. Subnet `ipv4-cidr-blocks`/`ipv4CidrBlocks` and VCN `byoipv6-cidr-blocks`/`byoipv6CidrBlocks` join existing aliases in a deduplicated union. Each distinct CIDR is a separate prefix record with its actual resource, compartment, and VCN identities.
- OCI bundle `metadata.collectedAt` supplies the source observation time for `verifiedAt`; local apply time is recorded separately in history. Unknown observation time remains unknown or preserves a known existing time. Live bundle coverage also records `collectionStartedAt`, exact scope, pagination and VCN context outcomes. Coverage never establishes deletion or that unobserved address space is free.

OCI API exported from `package:cidr_oci/cidr_oci.dart`:

- `OciAuthMode { apiKey, securityToken }`.
- Immutable selection types use required named parameters: `OciProfile(name, tenancyId, region, authMode)`, `OciConnection(executable, configFile, profile, tenancyId, authMode)`, `OciRegion(name, status, isHome = false)`, `OciCompartment(id, name)`, and `OciDiscovery(bundleJson, warnings = const [])`. Names here list constructor parameters; constructors are named-parameter Dart constructors.
- `OciCancellation()` exposes `isCancelled`, `whenCancelled`, and idempotent `cancel()`. `OciException(String message)` exposes safe actionable text, without raw command output.
- `OciInventoryClient` defines `profiles({configFile})`, `connection({required profile, configFile, executable, authMode})`, `regions(connection, {cancellation})`, `compartments(connection, {required region, cancellation})`, and `discover(connection, {List<String> regions = const [], bool allRegions = false, String? compartmentId, bool allCompartments = false, cancellation, onProgress})`. All return futures; results are respectively profile lists, resolved connection, region lists, compartment lists, and `OciDiscovery`.
- `OciCliClient()` implements the interface. Optional runner, environment, clock, timeout, and executable-candidate injection supports deterministic tests. This package imports neither Flutter nor SQLite and never applies imports.

The default adapter reads only allowlisted profile metadata, supports DEFAULT inheritance, suggests API-key or security-token authentication, and leaves key/token-file reads to the OCI CLI. Requests use an executable and argument array without a shell, explicit config/profile/auth/region/JSON output, an empty CLI rc file, and an isolated environment. Inherited OCI overrides are removed except `OCI_CLI_CERT_BUNDLE`; ordinary OS/proxy/TLS settings are retained. Each command is bounded to 60 seconds, complete discovery to 180 seconds for one selected pair or 1800 seconds for broader modes, followed by bounded process cleanup; OCI retries are bounded without a second Dart retry loop.

Region selection uses subscribed regions; clients enable READY entries. Compartment enumeration uses accessible active compartments and a synthetic tenancy-root entry. Discovery requires exactly one region mode (nonempty selected regions or allRegions) and one compartment mode (compartmentId or allCompartments). It trims/deduplicates regions and rejects blanks/conflicting modes before requests. All-region mode freshly enumerates READY subscriptions, reports non-READY exclusions and rejects zero READY. All-compartment mode freshly enumerates accessible active descendants from tenancy root plus root once. Compartments are enumerated once; each region/compartment pair collects all VCN/subnet pages sequentially. Single-compartment mode remains direct only. Each resource is stamped with its actual query region. Multi-region metadata omits the scalar region and retains regions; coverage records scope modes, completed pairs/counts and actual IDs. Accessible visibility does not guarantee network permissions or visibility of IAM-hidden resources. After regional lists complete, missing referenced VCNs are fetched once per region/ID as context. Denied/not-found context produces a warning, preserving the subnet's VCN reference without fabricating an explicit parent. Required-list failures, malformed output, cancellation, or timeout throw and return no applicable partial result. Successful discovery returns only an in-memory bundle describing a scoped observation over time, not a complete or transactionally consistent tenancy snapshot. Oracle's [VCN list](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/vcn/list.html), [subnet list](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/subnet/list.html), and [VCN get](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/vcn/get.html) define the underlying resource calls; profile and authentication conventions follow the [configuration](https://docs.oracle.com/en-us/iaas/Content/API/Concepts/sdkconfig.htm) and [session-token](https://docs.oracle.com/en-us/iaas/Content/API/SDKDocs/clitoken.htm) references.

Successful empty stdout normalizes to an empty collection only for the four known list commands (regions, compartments, VCNs, subnets), matching [OCI CLI 3.94.1 rendering](https://github.com/oracle/oci-cli/blob/v3.94.1/src/oci_cli/cli_util.py#L893-L947). Empty object-get output remains invalid. Malformed response errors identify the operation and expected field/type without including resource values or raw output. Empty results produce scope-appropriate guidance; broad results never ask the user to choose already-included descendants.

CLI: `runCidrctl` remains synchronous for existing commands. `runCidrctlAsync` handles `discover oci` and delegates existing commands unchanged; the executable awaits it. Discovery requires `--profile`, `--routing-domain`, repeated/comma-separated `--region` or `--all-regions`, and `--compartment-id` or `--all-compartments`; conflicting/missing scope modes fail before connection/database access; optional overrides are `--config-file`, `--oci-bin`, and `--auth api_key|security_token`. It previews by default; only `--apply` writes through the shared store transaction. Progress goes to stderr, warnings/preview to stdout. Ctrl-C cancels active collection; it cannot interrupt an already-running synchronous SQLite transaction. Exit codes remain 0 success/preview, 1 collection/storage/import failure, 2 usage error, and 3 manual allocation conflict. OCI conflicts remain reviewable after a valid import.

UI: dark desktop workspace titled CIDR Atlas, sidebar Inventory / Conflicts / History, search and domain/status filters, selectable table, details pane, add/edit dialog, CIDR checker, available subnet planner, import preview, JSON/CSV export, empty state with optional clearly labeled demo data. No production-looking data is preloaded. Uses synchronous store via controller; catches errors and shows readable messages. Local DB is under path_provider's Application Support/cidr_atlas/inventory.sqlite.

The existing Import dialog retains offline CSV/JSON selection and adds **Discover from OCI CLI**. `OciDiscoveryDialog({client, domain})` returns `OciImportSelection` with bundle, routing domain, and warnings. Metadata loads when the discovery dialog opens; scope requests require **Load scopes**, resource requests require **Discover inventory**. Authentication and path overrides, one/several READY regions or all READY subscriptions, a direct compartment or all accessible compartments/subcompartments/root, and manual comma-separated region/single-compartment fallback are available. Replaced selectors and busy scope/help controls are disabled or hidden. Routing domain is explicit. Dismissal cancels active work and ignores late results. Successful discovery uses the existing JSON parse, merged preview, validation/conflict display, and Apply path; it does not relabel OCI source identities. No automatic sign-in, background collection, or credential creation occurs.

Shared contract changes must remain consistent across the domain, persistence, CLI, and application packages.

Offline help uses `HelpTopic { gettingStarted, imports, ociDiscovery, planning, cidrBasics, routingDomains, cli }`, `showAtlasHelp(context, {topic})`, and `AtlasHelpDialog({initialTopic})`. The workspace and import/discovery/planner actions open contextual help with selectable guidance, copyable fictional CSV/JSON/CLI examples, and official reference URLs. Closing help retains its parent form/preview and performs no network or configuration access. CLI help explains prefix inputs and includes preview/apply examples without opening a database.

Import previews label their output as network CIDRs. Invalid or empty previews do not invoke merged preview validation, preventing duplicated errors. Only an explicitly live discovery with `isEmptyResult` receives a neutral completion state and scope retry action; malformed/structural errors remain visible. Apply remains disabled for empty results. Coverage/observation provenance remains available in an expandable disclosure with relevant warnings still summarized.

`recommend` accepts required `--pool`, `--routing-domain`, and exactly one `--prefix`/`--addresses`. Optional flags are `--parent`, `--growth-percent` (required with demand), `--additional` (zero), `--basis current|peak`, `--policy generic|oci_ipv4`, `--kind vcn|subnet`, `--limit` (12), `--format text|json`, `--apply`, `--name` (required with apply), and `--notes`. Policy defaults to generic for prefix and OCI IPv4 for demand. Kind defaults to VCN under an allocation and subnet otherwise; OCI subnet capacity cannot be claimed for a VCN recommendation. Preview is read-only for records/history; apply reserves the first candidate through `reserve`, inheriting parent metadata and retaining rationale. No-fit returns 1, usage 2, and a conflicting stale apply 3.

`VisualPlanner({required records, required onReserve})` and `CidrInspector({required cidr, policy})` present the shared engine. Planner inputs require explicit routing domain and invalidate stale results. Selection, zoom, bounded recommendations, hierarchy, OCI resource grouping, conflict/partial-space indicators, and CIDR details remain inventory-derived. The app opens the record editor before a strict reservation, retains the rationale, and requires recalculation if network/scope/hierarchy inputs change. This path never offers the manual conflict override. Observed gateway, route, DRG, and security connectivity is outside this milestone.

The planner uses a compact planning rail and a main map workspace; wide windows add an adjacent selected-network inspector. Narrower windows scroll without losing controls. Address hierarchy labels distinguish membership from connectivity.
