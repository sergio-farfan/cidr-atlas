# CIDR Atlas implementation contract

Author: Sergio Farfan <sergio.farfan@gmail.com>

Monorepo: `packages/cidr_core` (pure Dart), `packages/cidr_data` (Dart SQLite/imports), `packages/cidr_oci` (pure Dart OCI CLI adapter), `packages/cidr_cli`, `apps/cidr_atlas` (Flutter macOS first).

Core public API, exported from `package:cidr_core/cidr_core.dart`:

- `Cidr.parse(String input)` rejects invalid prefixes and host bits rather than silently changing the requested network. A prefix length with leading zeros (`10.0.0.0/08`, `::/00`) is rejected with `Invalid prefix length "/08". Use decimal without leading zeros.` Properties: `canonical` String, `prefixLength` int, `version` int, `addressCount` BigInt. Methods: `contains(Cidr)`, `overlaps(Cidr)`.
- enums `PrefixKind { allocation, vcn, subnet }`, `PrefixStatus { planned, reserved, active, retired }`.
- Immutable `PrefixRecord`: required named String `id`, `cidr`, `name`, `routingDomain`; named `kind` default `PrefixKind.vcn`, `status` default `PrefixStatus.reserved`; optional String fields default empty: `customer`, `tenancy`, `region`, `compartment`, `environment`, `owner`, `resourceId`, `vcnId`, `parentId`, `notes`, `source`; nullable DateTime `verifiedAt`. `toJson()`, `PrefixRecord.fromJson(Map<String,dynamic>)`, `copyWith(...)`. `toJson()` always writes `verifiedAt` as UTC ISO 8601 with `Z`, so CSV and JSON exports carry UTC values. `fromJson` stays tolerant of stored forms: values with `Z` or an offset return UTC, zone-less values are read as local wall-clock time (the form older versions persisted), and calendar rollover (`2026-02-30`, month 13, hour 24) is rejected with `Invalid verifiedAt timestamp.`
- `DateTime parseObservationTime(String)` is the strict observation-time parser for external input. It requires a date, a time (seconds and up to nine fractional digits optional, truncated to microseconds) and `Z` or a `±hh:mm` offset; it rejects zone-less and compact forms and calendar rollover, and returns UTC. Failures throw `FormatException` with `Observation time must be an ISO 8601 date and time with Z or a ±hh:mm UTC offset, such as 2026-10-15T18:30:00Z.` or `Observation time is not a valid calendar date, time, and offset.`
- `DateTime? tryParseStoredTimestamp(String)` is the tolerant reader `PrefixRecord.fromJson` uses for stored values written by `DateTime.toIso8601String`: values with `Z` or an offset return UTC, zone-less values return local wall-clock time, and calendar rollover or any other form returns null.
- `Conflict`: `PrefixRecord first`, `second`; String `reason`.
- `InventoryRules.conflicts(List<PrefixRecord>)` returns List<Conflict>. Only same routing domain conflicts. Retired prefixes ignored. Valid parent containment requires explicit, valid parentId chain OR VCN/subnet OCI resource relationship (matching vcn.resourceId and subnet.vcnId, same tenancy/region/domain). Arbitrary numeric containment is a conflict. Nonoverlapping unrelated resources are allowed. `first` always comes earlier in the input than `second`; results are ordered by the input position of `first`, then of `second`. Runtime is O(n log n + overlapping pairs).
- `InventoryRules.conflictsFor(Set<String> changedIds, List<PrefixRecord> records)` returns exactly the `conflicts(records)` entries whose `first` or `second` id is in `changedIds`, in the same order and orientation. Routing-domain/version buckets without a changed record are skipped and ancestry is evaluated only for overlapping pairs involving a change; cost is O(n log n + overlapping pairs in the touched buckets). The store write transaction, CLI `check`/`reserve`, the record editor and the CIDR checker use it.
- `InventoryRules.validate(List<PrefixRecord>)` returns List<String> for invalid CIDRs, blank identities/domains, duplicate ids, invalid/missing parent links, containment/kind mismatch and cycles. Conflicts remain reviewable, not structural validation errors. An explicit VCN parent that carries a resource id different from the subnet's `vcnId` is invalid (`subnet vcnId does not match its parent VCN resourceId.`).
- `InventoryRules.advisories(List<PrefixRecord>, {Set<String>? involving})` returns human-readable review notices that never block a save, reservation or import. It reports a subnet whose explicit parent is a placeholder VCN without a resource id while its `vcnId` names a comparable VCN recorded elsewhere: `Subnet <name> (<cidr>) has vcnId <ocid>, which names VCN <name> (<cidr>, <ocid>), but its parent is the placeholder VCN <name> (<cidr>) without a resource id. Clear or change the parent of <name>.` A VCN record is comparable when it is not retired, shares the subnet's routing domain, and matches tenancy and region wherever both records set them. The placeholder link stays a valid hierarchy for `validate`, `conflicts` and `available`, as in v0.3.0, so an inventory that v0.3.0 accepted stays writable and an OCI refresh that brings in the real VCN applies. With `involving`, only notices whose subnet, placeholder parent or named VCN has one of those ids are returned. Import previews add every notice for the combined inventory to `warnings`; CLI `check`/`reserve` print notices involving the candidate to stderr as `Advisory: <notice>` without changing the exit code; the app record editor shows them for the edited record as a non-blocking notice.
- `InventoryRules.available({required Cidr parent, required int prefixLength, required List<PrefixRecord> records, required String routingDomain, String? parentId, int limit = 8})` returns List<Cidr>; ignores retired entries. With parentId, validates the selected pool and ignores only that record and its explicit valid ancestors. Without it, every overlapping existing range blocks, and a malformed same-domain, non-retired record throws `ArgumentError('Cannot plan from invalid inventory: <id>: <message>')` rather than being skipped. Reject impossible prefix lengths.
- `AddressPolicy { generic, ociIpv4Subnet }`, `DemandBasis { current, peak }`. `AddressDemand({required BigInt addresses, required int growthPercent, BigInt? additionalAddresses, DemandBasis basis = DemandBasis.current})` exposes exact `targetAddresses = ceil(addresses * (100 + growthPercent) / 100) + additionalAddresses`. Growth is explicit and nonnegative; basis labels the input rather than removing an explicit allowance.
- `CidrDetails.from(Cidr, {AddressPolicy policy = AddressPolicy.generic})` exposes exact totals, host bits, network/range, nullable IPv4 mask, separately nullable provider assignable count/range, policy note, and `containingSupernet(int)`. OCI IPv4 subnet policy accepts only `/16..30`, subtracting three reserved addresses. Generic policy does not invent assignable counts for IPv4 or IPv6.
- `AddressInterval` uses inclusive `BigInt start/end` and an IP version. `AddressSpaceSummary` exposes disjoint free/blocked intervals, exact total/free/blocked addresses, total/free aligned slots, and largest free CIDR. Partial occupancy blocks a complete candidate slot without equating free addresses with free slots.
- `AddressPlanner.plan({required Cidr parent, required String routingDomain, required List<PrefixRecord> records, String? parentId, int? prefixLength, AddressDemand? demand, AddressPolicy policy = AddressPolicy.generic, int limit = 12})` requires exactly one of prefix or demand. Demand sizing initially supports OCI IPv4 subnets. Parent/domain/ancestor rules match `InventoryRules.available`, whose ascending ordering remains unchanged. Planning ranks maximal aligned free blocks by smallest fit, then address, considering aligned edges before bounded interior alternatives. `AllocationPlan` contains summary, prefixLength, nullable targetAddresses, bounded candidates, warnings; each candidate contains CIDR, details, rationale. `toJson()` uses public field names and decimal strings for all BigInt values. Availability is conditional on inventory coverage.

Data API exported from `package:cidr_data/cidr_data.dart`:

- `InventoryStore.open(String path)`, `InventoryStore.memory()`; synchronous `List<PrefixRecord> list()`, `void save(PrefixRecord, {bool rejectConflicts = false})`, `void delete(String id)`, `void deleteAll(List<String> ids)`, `void saveAll(List<PrefixRecord>)`, `List<AuditEntry> history({int limit = 100})`, `void close()`.
- `AuditEntry`: String `action`, `summary`; DateTime `at`.
- Atomic saves validate combined structure. rejectConflicts checks the candidate within the same write transaction (`conflictsFor` on the changed ids) for allocation workflows. Store enforces structure but allows conflict records so discovered overlaps are visible. When SQLite has already rolled back (full disk, I/O error, a `RAISE(ROLLBACK)` trigger), the original error surfaces; a failing `ROLLBACK` never masks it.
- `delete(id)` delegates to `deleteAll([id])`. `deleteAll` runs in one transaction: ids are deduplicated, unknown ids ignored, the remaining inventory validated once, and one audit entry written (`Deleted prefix <id>.` or `Deleted N prefixes: a, b.`); a no-op writes no audit entry. A record that a remaining record names as its parent is refused with `Cannot delete <name> (<cidr>): N child prefixes reference it: <name> (<cidr>), .... Delete or re-parent them first.` (`1 child prefix references it` for one child; up to five children are listed, then `and N more`).
- `InventoryStore.reserve(PrefixRecord)` creates a new record only, checking duplicate IDs, combined structure, and current conflicts inside one write transaction. Failure rolls back both record and audit writes. Planner UI/CLI use this path; imports retain their conflict-review behavior.
- `String defaultDatabasePath(Map<String, String> environment, {String? operatingSystem})` is the shared default inventory location for the CLI and the app; `package:cidr_cli` re-exports it. `operatingSystem` takes `Platform.operatingSystem` names and defaults to the current platform. macOS: `$HOME/Library/Application Support/cidr_atlas/inventory.sqlite` (`USERPROFILE` when `HOME` is unset). Windows: `%APPDATA%/cidr_atlas/inventory.sqlite`. Other systems: `$XDG_DATA_HOME/cidr_atlas/inventory.sqlite` when `XDG_DATA_HOME` is absolute, otherwise `$HOME/.local/share/cidr_atlas/inventory.sqlite`; a relative or empty `XDG_DATA_HOME` is ignored, as the XDG Base Directory specification requires (v0.3.0's CLI accepted a relative value). A missing variable throws `StateError` (`HOME is not set; specify --db.`, `APPDATA is not set; specify --db.`). The macOS and Windows paths are byte-identical to v0.3.0.
- `ImportPreview`: List<PrefixRecord> `records`; List<String> `errors`, `warnings`; String `source`; bool `get canApply` (nonempty records and no errors); `Set<String>? presentColumns` (null means every column was supplied; only CSV sets it); `PrefixRecord mergeOnto(PrefixRecord existing, PrefixRecord incoming)`, which copies only present columns onto an existing record and returns `incoming` when `presentColumns` is null.
- `ImportPreview.emptyRecordsMessage` is the canonical existing empty-record diagnostic. `isEmptyResult` classifies an empty record list with no errors other than that diagnostic. Raw errors and `canApply` remain unchanged; classification is presentation-only and never permits an empty apply.
- `InventoryImport.csv(String, {List<PrefixRecord> existingRecords = const []})`, `InventoryImport.json(String, {required String routingDomain, List<PrefixRecord> existingRecords = const []})`, `InventoryImport.exportCsv(List<PrefixRecord>)`, `InventoryImport.exportJson(List<PrefixRecord>)`.
- CSV merge: an id-matched non-OCI row updates only the columns in its header. An absent column keeps the existing value, including `status`, `kind`, `source` and `verifiedAt`; the parser defaults (`reserved`, `vcn`, `csv`) apply only to new records. A present but blank cell is taken at face value: text fields are cleared and blank `status`/`kind`/`source` reset to the defaults. JSON backup records still replace the whole existing record. Rows without an id keep the generated id (routing domain, kind, resource id, CIDR), so re-imports stay idempotent. Two id-less rows with the same generated id are an error (`CSV rows X and Y describe the same cidr, kind, routingDomain and resourceId without an id; add an id column to import both.`). An id-less row that matches an existing record whose name, or customer when that column is present, differs warns `CSV row X has no id and will replace existing record <name> (<cidr>, <domain>) whose name or customer differs; add ids to keep both.`; the match is then merged column by column as above.
- CSV export prefixes `'` to any cell matching `^'*[=+\-@\t\r]` so spreadsheets do not evaluate it as a formula; import removes exactly one leading `'` when the rest still matches, so exports round-trip losslessly. A hand-written CSV cell with a literal leading `'` before `=`, `+`, `-` or `@` loses that quote.
- CSV and backup `verifiedAt` use `parseObservationTime`, and values are stored in UTC. The zone-less form that v0.3.0 wrote in CSV exports and JSON backups (for example `2026-10-15T00:00:00.000`, and a date or date and time without a zone in general) is still accepted through `tryParseStoredTimestamp` and read as local time on the importing machine, as v0.3.0 did; the preview then adds one warning, `N verifiedAt values have no UTC offset and were read as local time.` (`1 verifiedAt value has no UTC offset and was read as local time.`). Calendar rollover and other forms are row errors with the strict message (`CSV row N: Invalid verifiedAt "<v>": <reason>`, `Backup record N: Invalid verifiedAt "<v>": <reason>`). OCI `metadata.collectedAt` remains tolerantly parsed.
- `InventoryStore.mergedImportRecords(ImportPreview)` returns the full dry-run inventory using the same merge rules as applyImport; `InventoryStore.applyImport(ImportPreview)` applies atomically, merging by id and preserving existing owner/notes/status/parentId/environment/customer where source is OCI. No absent entries deleted or retired. Audit coverage warning always explicit.
- OCI imports retain `ImportPreview.source == 'OCI JSON'` and incoming record source `oci`; merge protections depend on those identities. Subnet `ipv4-cidr-blocks`/`ipv4CidrBlocks` and VCN `byoipv6-cidr-blocks`/`byoipv6CidrBlocks` join existing aliases in a union deduplicated by canonical CIDR. Each distinct CIDR is a separate prefix record with its actual resource, compartment, and VCN identities.
- OCI previews built with `existingRecords` add reconciliation warnings, which also reach the import audit through `preview.warnings`: `<N> record(s) is/are marked retired but still observed live by OCI (e.g. ...); they stay retired, so their space is treated as free.` and `<N> record(s) has/have a newer observation than this bundle (e.g. <name> (<cidr>) observed at <iso>); applying rolls their observed fields and verifiedAt back to <iso>.` The merge rules are unchanged. A preview built without `existingRecords`, or with errors, carries neither notice; the CLI and app pass `store.list()`. Raw CLI input with `opc-next-page` on the root or a nested `vcns`/`subnets` map warns `Input is a single truncated OCI CLI page (opc-next-page present); rerun the list with --all. Unlisted ranges will appear free.`
- OCI bundle `metadata.collectedAt` supplies the source observation time for `verifiedAt`; local apply time is recorded separately in history. Unknown observation time remains unknown or preserves a known existing time. Live bundle coverage also records `collectionStartedAt`, exact scope, pagination and VCN context outcomes. Coverage never establishes deletion or that unobserved address space is free.

OCI API exported from `package:cidr_oci/cidr_oci.dart`:

- `OciAuthMode { apiKey, securityToken }`.
- Immutable selection types use required named parameters: `OciProfile(name, tenancyId, region, authMode)`, `OciConnection(executable, configFile, profile, tenancyId, authMode)`, `OciRegion(name, status, isHome = false, key)`, `OciCompartment(id, name, parentId, path)`, and `OciDiscovery(bundleJson, warnings = const [])`. Names here list constructor parameters; constructors are named-parameter Dart constructors. `OciRegion.key` is the optional subscription region key such as `IAD`. `OciCompartment.parentId` comes from `compartment-id`; `path` is the display path from the tenancy root (`root / prod / network`, a leading `…` segment when an ancestor is unlisted or the chain is cyclic), and `displayPath` returns `path ?? name`.
- `OciDiscoveryProgress(message, collectionTimeout, scopeCount, completedScopes = 0)` is one structured progress event: the same message text as `onProgress`, the whole-collection limit in effect, the region/compartment scope count (null until enumeration finishes), and completed scopes. `OciCollectionLimits.singleScope` (180 s) and `OciCollectionLimits.broadScope` (1800 s) are the default limits.
- `OciCancellation()` exposes `isCancelled`, `whenCancelled`, and idempotent `cancel()`. `OciException(String message)` exposes safe actionable text, without raw command output.
- `OciInventoryClient` defines `profiles({configFile})`, `connection({required profile, configFile, executable, authMode})`, `regions(connection, {cancellation})`, `compartments(connection, {required region, cancellation})`, and `discover(connection, {List<String> regions = const [], bool allRegions = false, String? compartmentId, bool allCompartments = false, cancellation, onProgress, onDiscoveryProgress})`. All return futures; results are respectively profile lists, resolved connection, region lists, compartment lists, and `OciDiscovery`.
- `OciCliClient({runner, environment, clock, commandTimeout = 120 s, collectionTimeout, executableCandidates})` implements the interface. `collectionTimeout` replaces the default whole-collection limit. Injection supports deterministic tests. This package imports neither Flutter nor SQLite and never applies imports.

The default adapter reads only allowlisted profile metadata, supports DEFAULT inheritance, suggests API-key or security-token authentication, and leaves key/token-file reads to the OCI CLI. Profile parsing follows Python ConfigParser, which the OCI SDK uses: a header followed by trailing text (`[PROD] # note`) is accepted; a line indented deeper than the preceding option continues it (kept for tenancy/region, ignored for credential keys); an equally indented line is a new option; an indented option directly after a header is an option, while an indented non-option line there, duplicate sections or options, `[]` and missing separators are rejected. The configuration file is the explicit `--config-file`/dialog path, otherwise `OCI_CLI_CONFIG_FILE` when set, otherwise `~/.oci/config`. The executable is the explicit path (a leading `~/` is expanded with `HOME`, or `USERPROFILE`), otherwise the first `oci` on PATH, then `$HOME/bin/oci`, `/opt/homebrew/bin/oci` and `/usr/local/bin/oci`. Requests use an executable and argument array without a shell, explicit config/profile/auth/region/JSON output, an empty CLI rc file, and an isolated environment. Inherited OCI overrides are removed from the child environment except `OCI_CLI_CERT_BUNDLE`; ordinary OS/proxy/TLS settings are retained. `OCI_CLI_CONFIG_FILE` is removed from the child but, as above, still selects the file the adapter passes explicitly. Every command passes `--connection-timeout 10 --read-timeout 15 --max-retries 3`; in OCI CLI 3.94.1 `--max-retries` is the SDK attempt count, so 3 means one try plus two retries, with no second Dart retry loop. Each command is bounded to 120 seconds; with `--all` pagination one command can make several HTTP requests, each with its own retries, so a long listing can reach this bound and fail closed. The whole-collection limit applies on top of it: 180 seconds for one region/compartment pair or 1800 seconds for broader modes unless `collectionTimeout` is set, followed by bounded process cleanup.

Region selection uses subscribed regions; clients enable READY entries. Compartment enumeration uses accessible active compartments and a synthetic tenancy-root entry. Discovery requires exactly one region mode (nonempty selected regions or allRegions) and one compartment mode (compartmentId or allCompartments). It trims and lowercases regions and rejects blanks/conflicting modes before requests. A region must be a full identifier matching `^[a-z]+(-[a-z]+)+-[0-9]+$` or a three-letter key in any case; keys are resolved to region names through one `iam region-subscription list` call, made only when a key is present. An unknown key, any other shape, or a failed key lookup throws with guidance naming the full identifier before any resource request. Regions are deduplicated after canonicalization, and resources, `--region` and metadata always use canonical names. OCI record ids include the region string, but natural identity does not compare regions: an existing record matches an incoming one with the same non-empty resource id (OCIDs are globally unique), kind, canonical CIDR, routing domain and compatible tenancy. A record that v0.3.0 stored under a non-canonical spelling (`IAD`, `US-ASHBURN-1`) is therefore refreshed in place: it keeps its id and planning fields and takes the canonical region. A VCN or subnet linked to it by an explicit parent that this refresh did not observe, and that holds exactly the old spelling, takes the canonical region too, so the link does not appear to cross regions. An inventory that already holds two copies of one OCID and CIDR under different spellings (for example from a refresh made before this rule) fails the refresh with `Multiple existing records match OCI resource ...`; delete the duplicate copy first. The collection limit is provisional during key resolution and is recomputed from the canonical regions, so `['IAD', 'us-ashburn-1']` is one scope under the 180-second limit, measured from the start of collection. All-region mode freshly enumerates READY subscriptions, reports non-READY exclusions and rejects zero READY. All-compartment mode freshly enumerates accessible active descendants from tenancy root plus root once. Compartments are enumerated once and returned tenancy root first, then sorted by path (case-insensitive, then exact, then OCID); all-compartment discovery visits them and records `metadata.compartmentIds` in that order. Only a nonempty compartment `id` is required; a missing name falls back to the OCID. Each region/compartment pair collects all VCN/subnet pages sequentially. Single-compartment mode remains direct only. Each resource is stamped with its actual query region. Multi-region metadata omits the scalar region and retains regions; coverage records scope modes, completed pairs/counts and actual IDs. Accessible visibility does not guarantee network permissions or visibility of IAM-hidden resources. After regional lists complete, missing referenced VCNs are fetched once per region/ID as context. Denied/not-found context produces a warning, preserving the subnet's VCN reference without fabricating an explicit parent. Required-list failures, malformed output, cancellation, or timeout throw and return no applicable partial result. Successful discovery returns only an in-memory bundle describing a scoped observation over time, not a complete or transactionally consistent tenancy snapshot. Oracle's [VCN list](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/vcn/list.html), [subnet list](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/subnet/list.html), and [VCN get](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/vcn/get.html) define the underlying resource calls; profile and authentication conventions follow the [configuration](https://docs.oracle.com/en-us/iaas/Content/API/Concepts/sdkconfig.htm) and [session-token](https://docs.oracle.com/en-us/iaas/Content/API/SDKDocs/clitoken.htm) references.

Successful empty stdout normalizes to an empty collection only for the four known list commands (regions, compartments, VCNs, subnets), matching [OCI CLI 3.94.1 rendering](https://github.com/oracle/oci-cli/blob/v3.94.1/src/oci_cli/cli_util.py#L893-L947). Empty object-get output remains invalid. Malformed response errors identify the operation and expected field/type without including resource values or raw output. Empty results produce scope-appropriate guidance; broad results never ask the user to choose already-included descendants.

CLI: `runCidrctl` remains synchronous for existing commands. `runCidrctlAsync` handles `discover oci` and delegates existing commands unchanged; the executable awaits it. Discovery requires `--profile`, `--routing-domain`, repeated/comma-separated `--region` or `--all-regions`, and `--compartment-id` or `--all-compartments`; conflicting/missing scope modes fail before connection/database access; optional overrides are `--config-file`, `--oci-bin`, `--auth api_key|security_token`, and `--collection-timeout SECONDS` (decimal integer 30..86400, validated before connection). The database path is resolved and checked before any OCI request; an existing file that cannot be opened as a CIDR Atlas inventory, and with `--apply` an existing database that cannot be opened for writing, also fail before collection (exit 1). An unwritable existing ancestor directory is still detected only after collection. It previews by default; only `--apply` writes through the shared store transaction. Progress goes to stderr: after connection `Using OCI configuration <file>, profile <profile> (<api_key|security_token> authentication).`, then once enumeration finishes `Collecting N region/compartment scope(s) with 2N sequential list requests within the S-second [default ]collection limit.` (from `OciDiscoveryProgress`), then per-scope lines. Discovery warnings and the preview go to stdout. A successful empty live discovery prints its warnings and `Discovery completed: no networks were found in the selected scope. No records were changed.` to stdout and exits 0, with or without `--apply`, without opening or creating the database. Ctrl-C cancels active collection; it cannot interrupt an already-running synchronous SQLite transaction. Exit codes remain 0 success/preview, 1 collection/storage/import failure, 2 usage error, and 3 manual allocation conflict. OCI conflicts remain reviewable after a valid import.

CLI usage errors (exit 2) include a blank `--db`, a missing `HOME`/`APPDATA` without `--db`, an unknown or missing command (`Usage error: unknown command X.`), a non-decimal `history --limit`, an OCI bundle imported without `--routing-domain` (inferred, `json` or `oci` type), and `--routing-domain` with a CSV or Atlas backup import. Two diagnostics go to stderr without changing exit codes: `Warning: created a new empty inventory at <path>. If you expected existing records, check --db.` whenever a command creates the database file, and, for `check`, `reserve`, `recommend`, `discover` and OCI JSON import, `Warning: routing domain "X" has no existing non-retired records, so nothing in it can conflict.` with optional `Did you mean: ...?` (case-insensitive equality or a small edit distance) and `Known routing domains: ...` (first 20). When the inventory has no non-retired records at all, the warning is `Warning: routing domain "X" has no existing records; the inventory has no non-retired records in any routing domain.` without suggestions. `check` and `reserve` also print `Advisory: <notice>` lines for `InventoryRules.advisories` notices involving the candidate. `recommend --apply` with no free candidate prints the plan followed by `No reservation was saved.` (not the preview hint) and exits 1. Routing-domain identity stays exact. `export --file` refuses the open database and its `-wal`/`-shm`/`-journal` files, compared after resolving symbolic links and `.`/`..` segments and ignoring case on macOS/Windows, with exit 2 (`Usage error: --file X is the open inventory database or one of its SQLite files; choose a different export path.`). Other existing files are replaced atomically: a temporary file in the same directory starts as a copy of the target, so its permission mode is kept, receives the new content and is renamed into place. A symbolic-link destination writes through to the end of its link chain, including a dangling link; a link loop fails with exit 1. `reserve` writes through `InventoryStore.reserve` (history action `reserve`); an existing `--id` prints the `already exists ... use the app to edit it` message with exit 1. `cidrctl --version` prints `cidrctl <version>` and a test ties it to `packages/cidr_cli/pubspec.yaml`.

`clear [--routing-domain DOMAIN] --yes` deletes local records only and never contacts OCI. Without `--routing-domain` every record is selected; with it, records whose routing domain equals the trimmed value exactly (case-sensitive). Usage errors (exit 2, nothing changed): missing `--yes` (`Usage error: clear deletes local inventory records and requires --yes. OCI resources are not changed. Run "cidrctl export --file BACKUP.json" first to keep a copy.`), a blank `--routing-domain`, and any positional argument. Clear never creates an inventory: a missing database file, including the default location, exits 1 with `Inventory not found: PATH. Clear never creates an inventory; check --db.` and creates no file or folder; a directory path exits 1 with `File error: The database path is a directory (PATH)`. An empty selection prints `No records to clear.` and exits 0 without writing; for a domain with no records the routing-domain warning precedes it, while a domain whose records are all retired is cleared without a warning. Otherwise the selected ids go through one `deleteAll` (one `delete` audit entry) and stdout reports `Cleared N records from the local inventory. OCI resources were not changed.` or `Cleared N records from routing domain DOMAIN. OCI resources were not changed.` (`1 record` for one). A store refusal, such as a record in another domain naming a cleared record as its parent, exits 1 with `Clear was not saved: <store message>` and deletes nothing. Root `--help` lists `clear` and adds `Clear deletes local records only and requires --yes; export a copy first.`

UI: dark desktop workspace titled CIDR Atlas, sidebar Inventory / Conflicts / Planner / History, search and domain/status filters, selectable table, details pane, add/edit dialog, CIDR checker, available subnet planner, import preview, JSON/CSV export, empty state with optional clearly labeled demo data. No production-looking data is preloaded. Uses synchronous store via controller; catches errors and shows readable messages. The local DB is `defaultDatabasePath(Platform.environment)` from `cidr_data` (`atlasDatabasePath` in `main.dart`), the same default as `cidrctl`: on macOS `~/Library/Application Support/cidr_atlas/inventory.sqlite`. The app must remain unsandboxed for that path to be shared. `main.dart` creates the parent directory before opening the store and passes `OciDiscoveryDialog.defaultClientFactory` to `AtlasApp`.

Workspace behavior: sample records carry source `demo`; `AtlasController.removeDemo()` deletes them, plus the six unlabeled `demo-*` records v0.3.0 created, through one `deleteAll`, and **Remove sample data** (inventory table header, with confirmation) appears while they exist. `loadDemo()` throws `FormatException` when the store is no longer empty, and **Export all** re-reads the database before writing.
